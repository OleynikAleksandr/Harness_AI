## 1. Фоновые (async) субагенты Claude

### 1.1 Наблюдаемый дефект

- Пока субагенты работают, их текст не появляется в окне субагента.
- Карточки субагентов показывают «failed», хотя агенты завершились успешно.
- После перезапуска приложения текст подтягивается (полная гидратация), но
  статус остаётся «failed».

### 1.2 Причина (проверено по файлам CLI 2.1.317)

Claude запускает субагентов в фоне. В родительском транскрипте:

- запуск — запись `user` с `toolUseResult.status: "async_launched"` и
  `agentId`;
- завершение — запись `queue-operation` (`operation: "enqueue"`) с текстом
  `<task-notification>`, где `<task-id>` — `agentId`, а `<status>` —
  итог (`completed` и т. п.); затем та же нотификация приходит как запись
  `user` со строковым `message.content`.

`ClaudeSubagentObserver` принимал любую запись `toolUseResult` с `agentId` за
финал: `async_launched` превращался в `failed`, после чего наблюдатель
переставал читать транскрипт агента. Опрос файлов шёл только во время хода
родителя, а с фоновыми агентами ход родителя заканчивается сразу после
запуска.

### 1.3 Решение (модуль `claude-provider`)

- `async_launched` — не финал: агент помечается как фоновый.
- Финал фонового агента берётся из `<task-notification>` (обе формы записи).
  Статус: `completed` → `completed`; `failed` → `failed`;
  `killed`/`stopped`/`cancelled` → `interrupted`; прочее → `failed`.
  Нотификации о неизвестных `task-id` (например, фоновые shell-команды)
  игнорируются.
- После конца хода родителя наблюдатель продолжает опрос, пока есть фоновые
  агенты без финального статуса. `closeSession` останавливает опрос полностью.
- Гидратация без активного хода, как и раньше, помечает агентов без финала
  как `interrupted`; агенты с нотификацией получают её статус. Core допускает
  смену одного финального статуса на другой, поэтому старые карточки «failed»
  исправляются при следующем открытии проекта.

## 2. Убрать проект из приложения

### 2.1 Требование пользователя

В списке проектов (меню переключателя workspace) по правой кнопке мыши
открывается контекстное меню. Первый пункт — «Убрать из Harness AI». Проект
не удаляется с диска; из приложения убираются все ссылки на него.

### 2.2 Что значит «все ссылки»

- запись в реестре `~/.harness-ai/workspaces.json` (или `HARNESS_AI_HOME`);
- загруженные в Core сессии проекта: подписки и provider-сессии закрываются,
  записи удаляются из памяти; файлы истории в папке проекта не трогаются;
- данные провайдеров в домашних каталогах приложения, привязанные к пути
  проекта: `~/.harness-ai/providers/*/home/.claude/projects/<slug>` и
  `~/.harness-ai/providers/*/home/Library/Caches/claude-cli-nodejs/<slug>`,
  где `<slug>` — путь проекта, в котором каждый символ, кроме букв и цифр,
  заменён на `-`.

Папка проекта (`.harness/**`, `.claude/**`, git) остаётся без изменений:
повторное «Open Project» возвращает проект вместе с историей сессий.

### 2.3 Контракты

- Core RPC `remove-workspace` `{workspaceId}` →
  `{ok: true, activeWorkspaceId, workspaces}` или
  `{ok: false, code, error}`; коды `UNKNOWN_WORKSPACE`,
  `BUILT_IN_WORKSPACE` (встроенный workspace `harness-ai-local` не убирается).
- Если убран активный проект, активным становится встроенный workspace.
- Маршрут workspace (list/add/select/remove, снимок реестра, provisioning)
  выносится из `core-runtime-api.ts` в `core-workspace-rpc.ts`: API
  достиг лимита 500 строк.
- `WorkspaceRegistryFacade.removeWorkspace(id)`;
  `SessionRequestHandlerFacade.releaseWorkspaceSessions(workspaceId)`;
  `ProviderHomeManagerFacade.removeWorkspaceResidue(workspacePath)`.
- IPC `remove-workspace` (preload `removeWorkspace(workspaceId)`).
- Renderer: компонент меню проектов с контекстным меню (in-app, без native
  dialogs); пункт не показывается для встроенного workspace. Подтверждение не
  требуется: действие обратимо через «Open Project».
